# I-16

## What it is

Keys beside state: the earlier bridge actor signed with node keys, and the earlier signer still sits in the process that holds
the book (`notes/BRIDGE-REQUIREMENTS.md` §5, "Bloque's internal incident records"). This is a custody matter, so this runbook
is how to check that the separation still holds.

What bezent does: key material does not live in the component that holds state, is never readable from an environment, a
configuration, a log or an error, and the signer signs only what matches an intent the coordinator recorded (`REQ-AR-3`,
`REQ-CU-1`, `REQ-KY-1`, `INV-9`). The signer refuses a caller that runs as its own user and refuses to start beside one; its store
login can act as the signer role and nothing more; every role holds exactly its rows of the grant matrix. A test
configuration is refused against a store with a production network (`REQ-KY-6`). A signature bezent did not record is a key
compromise (`REQ-IC-4`). The signer's health check means its store answers and its socket exists, not that its keys sign
(`deploy/health.md`).

## Pages

`key-compromise` (`../pages/key-compromise.md`).

## Confirm

```sql
SELECT id, kind, subject, actor, justification, recorded_at FROM admin_actions
 WHERE kind IN ('key-rotation', 'credential', 'bound-change') ORDER BY id DESC LIMIT 20;
```

The store cannot show where a process runs. From the deployment's own notes, check that the signer and the core run under
different user ids and in different tasks, that no key or key location appears in any environment or configuration of the
core, and that the signer's store login is its own (matrix: `crates/store/src/grants.rs`).

## Do

- If the separation is found broken, pause (`operator_pause`, no scope: all assets, networks and directions) and treat it as
  `../pages/key-compromise.md`; in-flight work keeps being observed.
- Record each rotation, credential or bound change made outside the store with `operator_record` the same day. Lift a
  pause only with a second person: `operator_request_unpause`, then `operator_approve_unpause` by a different login.

## Never

- No key, token or key location in the store, a ticket, a log, an environment or this repository (`REQ-KY-1`).
- No test key on a production network, and no production key on a test network (`REQ-KY-6`).
- No UPDATE or INSERT on signatures, intents or admin records; no signing outside a recorded intent (`INV-9`, `REQ-GV-5`).
